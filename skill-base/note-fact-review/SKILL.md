# 个人笔记事实审核与订正

审核目标 Markdown 笔记的事实准确性与结构完整性，输出“审核-改动对照表”。报告默认只在回复中给出，不额外落盘。

## 参数（缺失则询问或取默认）
| 参数 | 默认 | 说明 |
|---|---|---|
| target_file | 必需 | 要审核的 Markdown 文件绝对路径 |
| scope | quick | quick=仅断链/错别字/TODO 扫描；deep=联网核验+重写 |
| mode | balanced | objective(客观改写) / keep-voice(保留口吻只纠错) / balanced(事实客观、比喻保留)；仅 deep 生效 |
| web_check | true | 是否联网核验；scope=deep 时生效，私密/公司内部文档应询问或转 false |
| domain_hint | 空 | 可选领域提示（如“软件测试”），定位内置易错点 |

## 流程

### 1. 检索与准备（只读）
- 可读取同领域笔记作为审核对照素材（直接用 Grep/Read 工具查阅 vault 文件，不再依赖 obsidian-rag 等本地语义检索）。
- 读取 target_file 全文（保留行号引用）；读取根 AGENTS.md / CLAUDE.md / README.md（存在时），确认约定。
- 含凭据文件（如 config.md）禁止读取。

### 2. 备份（修改前必做）
- 复制 target_file 为 `<原名>.bak.YYYY-MM-DD`；仓库为 git 时可用 git diff 呈现改动。
- 写入遵循仓库约定：Obsidian 仓库的笔记写操作走 obsidian CLI；批量维护例外完成后必须用 CLI 校验 + reload。

### 3. 审核
- quick：结构盘点（标题层级 + 每节状态）+ 未完成章节（TODO / 待补充 / 占位符）+ 错别字/断句 + 图片引用与 [[双链]] 断链扫描。
- deep：在 quick 基础上增加事实核验（时间线、版本号、量化指标、概念定义、公司/产品关系）与重写（按 mode）：弱化个人口吻或保留；合并重复章节；补新概念小节（文档用了却没解释的术语）；时效数据标注“截至 YYYY-MM”；主观评价标注“个人观点”。
- 错误分类：事实错误 / 过时 / 无出处断言 / 逻辑矛盾 / 错别字 / 格式问题。

### 4. 联网核验（scope=deep 且 web_check=true）
- 对可疑点生成中英检索词；优先官方来源（官方文档 > 权威站点 > 社区）。
- 每条记录“原文 → 订正 → 来源”；检索矛盾时取多来源共识并标注“待确认”。

### 5. 校验
- 通读重写后全文：无断句、乱码；图片引用指向存在的文件（复用 vault-cleanup 规则：`./assets/` 带前缀、`![[...]]` 嵌入引用保留）。
- Obsidian 仓库用 `obsidian unresolved` 查断链；涉及改名/移动时同步 [[双链]]。

### 6. 收尾
- 输出“审核-改动对照表”：原文位置 | 改后位置 | 原问题 | 处理(订正/保留并补全/刷新/合并/新增) | 来源。报告默认只在回复中给出。

## 约束
- 不编造知识库里没有的内容；核验不到的点明确写“待确认”。
- 修改前必备份；删除 / 大改用户笔记须用户确认。
- 私密 / 公司内部文档默认 scope=quick，联网前先询问。
- 联网结果可能过时，时效数据以官方最新发布为准，文中标注截至时间。
- 不读取、不修改 config.md（凭据文件）。
