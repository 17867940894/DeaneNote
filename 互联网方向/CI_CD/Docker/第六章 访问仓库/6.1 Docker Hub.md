# 6.1 Docker Hub

> **来源**：Docker 入门教程


## 一、什么是 Docker Hub

[Docker Hub](https://hub.docker.com/) 是 Docker 官方维护的公共镜像仓库，也是全球最大的容器镜像库。

它提供了：

| 功能 | 说明 |
|---|---|
| **官方镜像** | 由 Docker 官方和软件厂商（如 Nginx、MySQL、Node.js）维护的高质量镜像 |
| **个人/组织仓库** | 用户可以上传自己的镜像 |
| **自动构建** | 与 GitHub/Bitbucket 集成的历史功能，已标记为 deprecated，计划于 **2027-04-01** 完全退役 |
| **Webhooks** | 镜像更新时触发回调 |


## 二、核心功能

### 1. 搜索镜像

通过 `docker search` 命令查找官方仓库中的镜像：

```bash
$ docker search centos
NAME      DESCRIPTION                                  STARS     OFFICIAL
centos    DEPRECATED; The official build of CentOS.    7000+     [OK]
```

> **技巧**：始终优先使用 `OFFICIAL` 标记为 `[OK]` 的镜像，安全性更有保障。

### 2. 拉取镜像

```bash
docker pull nginx:alpine
```

### 3. 推送镜像

**登录 Docker Hub**：

```bash
# 默认走 Device Code Web Flow（浏览器认证）
$ docker login

# 在非交互 CI 环境中，推荐结合 --username 与 --password-stdin
$ cat "$HOME/.dockerhub-token" | docker login --username username --password-stdin
```

**打标签并推送**：

```bash
# 1. 标记镜像
$ docker tag myapp:v1 username/myapp:v1

# 2. 推送
$ docker push username/myapp:v1
```


## 三、限制与配额

### 3.1 镜像拉取限制（Pull Rate Limit）

Docker Hub 对不同类型用户实施拉取速率限制（基于 **6 小时周期**）：

| 用户类型 | 限制 |
|---|---|
| **匿名用户**（未登录） | 每 6 小时 100 次请求 |
| **免费账户**（已登录） | 每 6 小时 200 次请求 |
| **Pro/Team/Business 账户** | 无限制（公平使用政策） |

> **注意**：Docker 曾计划于 2025 年 4 月调整拉取限制策略，但在 2025 年 2 月宣布取消该计划。目前付费订阅用户享有无限制拉取额度。建议在 CI/CD 环境中始终配置 `docker login` 以获得更高的拉取额度。

### 3.2 滥用限流（Abuse Rate Limiting）

除了 Pull Rate Limit 之外，Docker Hub 对所有用户（含已认证及付费用户）还实施了**滥用保护限流（Abuse Rate Limiting）**，根据网络出口 IP（IPv4 或 IPv6 /64 子网）计算整体请求频率，阈值动态触发（通常为每分钟数千级别请求）。

**两种限流的区别**：

| 类型 | 触发条件 | 报错信息 |
|---|---|---|
| **Pull Rate Limit** | 拉取量达到上限 | `429 Too Many Requests`，包含 `toomanyrequests: You have reached your pull rate limit` 提示，常附有账户升级链接 |
| **Abuse Rate Limit** | 接口请求频率过高 | 仅返回简化的 `429 Too Many Requests`，不分付费与否 |

> **提示**：如果在 CI/CD 环境遇到 429 错误：
>
> 1. 先甄别具体是哪类限流。Pull Rate Limit 只需在 CI 中配置 `docker login`（使用有效账号）即可解除
> 2. 如果是 Abuse 频控导致，应考虑搭建私有仓库作为拉取缓存代理（Registry pull-through cache）
> 3. 使用国内镜像加速器


## 四、安全最佳实践

### 1. 启用 2FA（双因素认证）

在 Account Settings → Security 中启用 2FA，保护账号安全。启用后，CLI 登录需要使用 **Access Token** 而非密码。

### 2. 使用 Access Token

> ⚠️ **警告**：绝不要在脚本或 CI/CD 系统中直接使用 `-p` 参数传递密码或 Token（如 `docker login -p xxx`）！这会导致凭证暴露在命令历史、进程列表和终端输出中。

**正确做法**：

1. 在 Docker Hub → Account Settings → Security → Access Tokens 创建 Token（PAT）
2. 将 Token 保存在权限受限的本地文件或 CI secret 中，通过标准输入（stdin）传递给 Docker：

```bash
chmod 600 "$HOME/.dockerhub-token"
cat "$HOME/.dockerhub-token" | docker login --username username --password-stdin
```

### 3. 关注镜像漏洞

Docker Hub 提供 **Docker Scout** 安全扫描功能：

| 用户类型 | 扫描功能 |
|---|---|
| **所有用户** | 官方镜像漏洞扫描结果免费可见 |
| **免费层** | 可覆盖 1 个私有仓库的持续扫描 |
| **付费用户** | 可扫描更多仓库 |


## 五、Webhooks

当镜像被推送时，可以自动触发 HTTP 回调（例如通知 CI 系统部署）。

**配置方法**：仓库页面 → Webhooks → Create Webhook。


## 六、自动构建（已弃用）

> ⚠️ Docker Hub Automated Builds 已被 Docker 标记为 **deprecated**，计划于 **2027-04-01** 完全退役。

- **新项目**：应优先使用 GitHub Actions、Buildx 或自有 CI 构建并推送镜像
- **仍在迁移期内的旧仓库**：链接 GitHub/Bitbucket 仓库后，代码提交或打标签时仍可自动构建，但不要将其作为新架构的默认方案


## 七、命令速查

| 命令 | 说明 |
|---|---|
| `docker search <关键词>` | 在 Docker Hub 搜索镜像 |
| `docker pull <镜像名>` | 从 Docker Hub 拉取镜像 |
| `docker login` | 登录 Docker Hub |
| `docker tag <镜像> <用户名/仓库:标签>` | 为镜像打标签准备推送 |
| `docker push <用户名/仓库:标签>` | 推送镜像到 Docker Hub |
| `docker logout` | 登出 Docker Hub |
