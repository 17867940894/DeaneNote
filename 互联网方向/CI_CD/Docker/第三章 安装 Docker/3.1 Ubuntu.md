# 3.1 Ubuntu

> **来源**：Docker 入门教程


## 一、为什么推荐 APT 源安装而不是脚本？

虽然 Docker 官方提供了便捷的安装脚本（`get.docker.com`），但在生产环境中**强烈推荐通过 Docker 官方 APT 仓库安装**：

| 考量维度 | APT 源安装 | 脚本安装 |
|---|---|---|
| **版本管理** | ✅ 可像其他系统包一样升级、回滚和锁定版本 | ❌ 难以管理版本 |
| **安全更新** | ✅ 官方仓库持续发布新版本和安全修复 | ⚠️ 需手动重新执行脚本 |
| **团队一致性** | ✅ 团队容易锁定同一版本 | ❌ 不同机器版本可能不一致 |
| **卸载清理** | ✅ APT 包管理系统负责清理 | ❌ 清理往往不够彻底 |

> ⚠️ **切勿在没有配置 Docker APT 源的情况下直接使用 `apt` 命令安装 Docker。**


## 二、准备工作

### 2.1 系统要求

当前受支持的 Ubuntu 64 位版本（以官方 [安装文档](https://docs.docker.com/engine/install/ubuntu/) 为准）：

- Ubuntu Resolute Raccoon 26.04（LTS）
- Ubuntu Questing Quokka 25.10
- Ubuntu Noble 24.04（LTS）
- Ubuntu Jammy 22.04（LTS）

> ⚠️ **警告**：Ubuntu 20.04 LTS 已不在 Docker 当前支持列表中，不建议用于新部署。

**平台支持**：

- **LTS 版本**：支持 amd64、arm64、armhf、ppc64el、s390x 共 5 个平台，获得 5 年升级维护支持
- **非 LTS 版本**：支持的平台通常较少

### 2.2 卸载旧版本

Docker 官方建议先卸载可能冲突的非官方软件包：

```bash
$ for pkg in docker.io docker-compose docker-compose-v2 docker-doc podman-docker containerd runc; do
    sudo apt remove $pkg
done
```


## 三、使用 APT 安装（推荐）

### 3.1 安装基础依赖

```bash
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
```

### 3.2 添加 Docker 签名密钥

```bash
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

### 3.3 添加 Docker APT 仓库

```bash
$ sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
```

> 如果需要测试频道，可将 `Components: stable` 改为 `test`。

### 3.4 安装 Docker Engine

```bash
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```


## 四、使用脚本自动安装（测试/开发环境）

在测试或开发环境中，Docker 官方提供了便捷安装脚本，但官方**不建议将其作为生产环境的标准安装方式**。

```bash
# 下载脚本并预览执行动作（推荐先做）
$ curl -fsSL https://get.docker.com -o get-docker.sh
$ sudo sh ./get-docker.sh --dry-run

# 确认无误后执行安装
$ sudo sh ./get-docker.sh

# 若需要测试频道：
# curl -fsSL https://test.docker.com -o test-docker.sh
# sudo sh ./test-docker.sh
```


## 五、启动 Docker

```bash
sudo systemctl enable --now docker
```


## 六、建立 docker 用户组

默认情况下，`docker` 命令使用 Unix socket 与 Docker 引擎通讯。只有 `root` 用户和 `docker` 组的用户才可以访问 Docker 引擎的 Unix socket。

```bash
# 建立 docker 组
$ sudo groupadd docker

# 将当前用户加入 docker 组
$ sudo usermod -aG docker $USER
```

> ⚠️ **安全警告：`docker` 用户组等同于 `root` 权限**
>
> 将用户加入 `docker` 组免去了每次执行 `docker` 命令时输入 `sudo` 的繁琐，但这也意味着该用户可以轻易获取主机的最高 root 权限。在多用户共享的生产系统上，切勿随意将普通用户加入此组。
>
> 更安全的替代方案是使用官方提供的 **[Rootless 模式](https://docs.docker.com/engine/security/rootless/)**，允许在没有任何 root 权限的情况下运行 Docker。

加入用户组后，需**退出当前终端并重新登录**。


## 七、测试 Docker 是否安装正确

```bash
docker run --rm hello-world
```

## 安装方式对比总结

| 安装方式 | 适用场景 | 优点 | 缺点 |
|---|---|---|---|
| **APT 源安装** | 生产环境（推荐） | 版本管理、安全更新、一致性、卸载干净 | 步骤稍多 |
| **脚本安装** | 测试/开发环境 | 便捷快速 | 版本难管理、清理不彻底 |
