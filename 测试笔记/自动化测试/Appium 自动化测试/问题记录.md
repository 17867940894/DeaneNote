### Appium Inspector 连接设备失败问题总结

**问题现象：**

使用 Appium Inspector 创建 Session 时，报错：

```text
WebDriverError: Device 127.0.0.1:7555 was not in the list of connected devices
```

同时无法连接 Appium Server。

**问题原因：**

Appium Inspector 配置中的 `appium:udid` 与 adb 实际连接的设备 ID 不一致。

Inspector 中配置：

```json
"appium:udid": "127.0.0.1:7555"
```

但执行：

```bash
adb devices
```

发现实际设备为：

```text
emulator-5554    device
```

Appium 会通过 adb 查找指定 udid 的设备，如果设备列表中不存在对应 ID，就会创建 Session 失败。

**解决方法：**

1. 查看当前 adb 连接设备：

```bash
adb devices
```

1. 将 Appium Inspector 中的：

```json
"appium:udid": "127.0.0.1:7555"
```

修改为实际设备：

```json
"appium:udid": "emulator-5554"
```

或者删除 `udid` 配置，让 Appium 自动选择唯一设备。

1. 同步修改项目 `config.yaml`：

```yaml title="config/config.yaml"
capabilities:
  udid: "emulator-5554"
```

1. 重新启动 Appium Server，并在 Inspector 中重新创建 Session。

**经验总结：**

Appium 的 `udid` 必须与 `adb devices` 输出的设备 ID 完全一致。模拟器端口（例如 MuMu 的 `127.0.0.1:7555`）只是某些环境下的连接方式，不能直接当作固定配置。遇到设备连接问题时，优先执行：

```bash
adb devices
```

确认真实设备 ID，再配置 Appium 的 `udid`。这类问题本质上不是 Appium 配置错误，而是 **Appium 配置与 adb 设备状态不一致**。

### PowerShell 执行 `grep` 命令报错问题总结

**问题现象：**

在 Windows PowerShell 中执行：

```powershell
adb shell dumpsys window | grep mCurrentFocus
```

报错：

```text
grep : 无法将“grep”项识别为 cmdlet、函数、脚本文件或可运行程序的名称
```

**问题原因：**

`grep` 是 Linux/macOS 环境中的文本过滤命令，Windows PowerShell 默认不包含该命令。

Appium/Android 教程中常见命令：

```bash
adb shell dumpsys window | grep mCurrentFocus
```

适用于 Linux 环境，在 Windows 下需要替换。

**解决方法：**

Windows PowerShell 使用：

```powershell
adb shell dumpsys window | findstr mCurrentFocus
```

或者使用 PowerShell 原生命令：

```powershell
adb shell dumpsys window | Select-String "mCurrentFocus"
```

执行后可以查看当前 Activity：

```text
mCurrentFocus=Window{xxxx u0 com.tal.kaoyan/com.kaoyan.kylogin.ui.login.LoginKActivity}
```

其中：

```text
com.tal.kaoyan
```

对应：

```text
appPackage
com.kaoyan.kylogin.ui.login.LoginKActivity
```

对应：

```text
appActivity
```

**经验总结：**

在 Windows 环境执行 Android/Appium 命令时，需要注意系统命令差异：

| Linux/macOS | Windows PowerShell      |
| ----------- | ----------------------- |
| grep        | findstr / Select-String |
| cat         | type / Get-Content      |
| ls          | dir / Get-ChildItem     |

遇到 Appium 启动应用失败或 `appActivity` 不确定时，可以通过：

```powershell
adb shell dumpsys window | findstr mCurrentFocus
```

快速获取当前页面的 `package` 和 `activity` 信息，用于配置 Appium Capability。

### Appium 手势自动化问题记录

#### 环境

- Appium **3.6.0** + Android uiautomator2 驱动
- appium-Python-client **3.1.0**，Selenium 4.21.0
- 设备：MuMu 模拟器（emulator-5554），App：考研帮

#### 问题

在 Appium 3.x 下，**旧手势 API 全部失效**，测试执行手势时报错：

- `TouchAction`/`MultiAction` → `UnknownMethodException`（404，端点被移除）
- 手写 W3C Actions（`ActionChains`/`ActionBuilder`）→ `InvalidElementStateException`（输入链校验严格）
- `mobile: pinchOpen` → `UnknownMethodException`（命令名错误）

#### 结论

优先使用 **uiautomator2 驱动原生 `mobile:*Gesture` 扩展命令**，稳定且官方推荐。

#### 修复方案

##### 长按（long_press）

改用 `mobile: longClickGesture`：

```python
self.driver.execute_script(
    "mobile: longClickGesture",
    {"x": x, "y": y, "duration": int(duration * 1000)},  # duration 单位毫秒
)
```

##### 双指缩放（pinch）

改用 `mobile: pinchOpenGesture` / `mobile: pinchCloseGesture`：

```python
command = "mobile: pinchOpenGesture" if zoom_in else "mobile: pinchCloseGesture"
self.driver.execute_script(command, {
    "left": center_x - half, "top": center_y - half,
    "width": half * 2, "height": half * 2,
    "percent": percent,   # 必须是 0.0~1.0 浮点
    "speed": speed,
})
```

#### 关键注意点

- **命令名**：是 `pinchOpenGesture`，不是 `pinchOpen`
- **坐标**：不传 `element` 时必须提供 `left/top/width/height`
- **percent**：范围是 **0.0~1.0**（浮点），不是 1-100
- 手势目标页面需支持相应操作，否则命令能执行但无实际效果

### 误用 self.driver 导致属性缺失

**报错信息**

```python title="testcases\test_demo.py"
    def test_gesture_demo(self, driver):
        # 截图（注意文件名需要 .png 后缀，否则 Selenium 会告警）
        driver.save_screenshot("login_success.png")
        print("截图已保存: login_success.png")

        # 等待 Toast 演示：Toast 只有在触发对应操作后才会出现，
        # 本 demo 未触发"密码错误"场景，这里演示 API 用法并容错处理。
        try:
            toast = WaitHelper(driver).toast_visible("密码错误", timeout=3)
            print(toast.text)
        except Exception as e:
            print(f"本次未捕获到 Toast（预期内，demo 未触发登录失败）: {type(e).__name__}")

```

**问题背景**

`conftest.py` 中定义了一个 session 级别的 `driver` fixture，负责创建 Appium WebDriver 会话：

```python title="/conftest.py"
@pytest.fixture(scope="session")
def driver():
    drv = create_driver()
    drv.implicitly_wait(5)
    yield drv
    drv.quit()
```

pytest 的 fixture 是通过**测试方法参数名匹配**注入的，即 `driver` 只在方法作用域内可用，并不会成为测试类实例的属性。

**根因分析**

`test_demo.py` 的方法签名 `def test_gesture_demo(self, driver)` 是正确的，参数 `driver` 已由 pytest 注入；但方法体内全部误写成了 `self.driver`，试图从实例属性上取，而 `TestDemo` 类从未定义过 `driver` 属性，因此抛 `AttributeError`。

**修复方式**

- 统一将方法体内的 `self.driver` 改为参数 `driver`
- 与项目中其他测试文件保持一致的写法（`test_login_wait.py`、`test_login_locators.py` 均直接使用参数 `driver`）

### 错误依赖 driver.wait 属性

**报错信息**

```bash
AttributeError: 'WebDriver' object has no attribute 'wait'. Did you mean: 'wait_activity'?
```

**问题背景**

原 demo 代码里调用了 `self.driver.wait.toast_visible("密码错误")`，期望 WebDriver 自带 `wait` 属性（类似某些 Appium 教程中的写法），但实际上当前环境（appium-Python-client 3.1.0 + Selenium）的 `WebDriver` 对象**没有 `wait` 属性**。

**根因分析**

Toast 的等待逻辑被封装在项目自己的工具类中：

```python title="utils/wait_helper.py"
def toast_visible(self, text: str, timeout: int = 5):
    """等待并获取安卓 Toast 提示（文本匹配）"""
    locator = (AppiumBy.XPATH, f'//android.widget.Toast[@text="{text}"]')
    return WebDriverWait(self.driver, timeout).until(
        EC.presence_of_element_located(locator)
    )
```

- `WaitHelper` 内部用 `WebDriverWait` + XPath 定位 `//android.widget.Toast[@text="..."]` 实现 Toast 等待
- `BasePage` 中的 `self.wait = WaitHelper(driver, timeout=10)` 也是复用了这个封装，说明正确用法是创建 `WaitHelper` 实例，而不是直接用 `driver.wait`

**修复方式**

- 引入 `from utils.wait_helper import WaitHelper`
- 改为 `WaitHelper(driver).toast_visible("密码错误")`，把 `driver` 传入构造器
