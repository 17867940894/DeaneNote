## 一、三种等待对比

| 类型 | 写法 | 行为 | 移动端评价 |
| --- | --- | --- | --- |
| 强制等待 | `time.sleep(5)` | 死等 5 秒 | ❌ 坚决不用（拖慢、仍 flaky） |
| 隐式等待 | `driver.implicitly_wait(10)` | 全局：每次 `find_element` 找不到就轮询最多 10s | ⚠️ 仅作兜底，**不要和显式混用** |
| 显式等待 | `WebDriverWait(...).until(EC.xxx)` | 针对某个条件精准等待 | ✅ 移动端主力，必须掌握 |

> [!warning]
>
> 隐式 + 显式混用 = 等待时间叠加爆炸
> 隐式等待设 10s、显式再设 10s，某些场景下实际可能等 20s 甚至更久，且行为不可预测。**工程规范：隐式等待只在 `conftest.py` 设一个小的兜底值（如 5s），所有业务等待一律用显式**。

## 二、显式等待核心 API（与 Selenium 通用）

```python title="utils/wait_helper.py"
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
# 元素可见（最常用：能看见才能点/读）
WebDriverWait(driver, 10).until(
    EC.visibility_of_element_located((AppiumBy.ID, "com.tal.kaoyan:id/login_login_btn"))
)

# 元素可点击（点击前必等）
WebDriverWait(driver, 10).until(
    EC.element_to_be_clickable((AppiumBy.ID, "..."))
)

# 元素存在（不要求可见，常用于判断 DOM 是否在）
WebDriverWait(driver, 10).until(
    EC.presence_of_element_located((AppiumBy.ID, "..."))
)

# 元素消失（加载圈、弹窗关闭）
WebDriverWait(driver, 10).until(
    EC.invisibility_of_element_located((AppiumBy.ID, "loading"))
)
```

> [!tip]
>
> 移动端为什么比 Web 更依赖显式等待
> App 启动有冷启动耗时、页面有转场动画、列表要网络加载。Web 端 `find_element` 秒回，App 端常常 "元素还在路上"。所以 **每个关键操作前都包一层显式等待**，是 App 自动化稳定的根本。

## 三、WaitHelper 强化版（移动端专属）

在 [[01-环境搭建与工程初始化#三、第一个工程骨架（工程化优先，拒绝零散脚本）]] 基础上，补充移动端专用等待：

| 方法                   | 对应 EC                           | 用途          |
| ---------------------- | --------------------------------- | ------------- |
| `element_visible()`    | `visibility_of_element_located`   | 元素可见      |
| `element_clickable()`  | `element_to_be_clickable`         | 元素可点击    |
| `element_present()`    | `presence_of_element_located`     | 元素存在      |
| `element_disappear()`  | `invisibility_of_element_located` | 元素消失      |
| `toast_visible()`      | Toast XPath                       | Android Toast |
| `is_element_visible()` | try/except                        | 判断元素状态  |

```python title="utils/wait_helper.py"
"""
WaitHelper
Appium 显式等待工具类

功能：
1. 等待元素可见
2. 等待元素可点击
3. 等待元素存在
4. 等待元素消失
5. 等待 Toast
6. 判断元素是否可见
"""

from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
from appium.webdriver.common.appiumby import AppiumBy


class WaitHelper:
    def __init__(self, driver, timeout: int = 10):
        self.driver = driver
        self.timeout = timeout

    def element_visible(self, locator, timeout=None):
        """
        等待元素可见
        使用场景：
        - 获取文本
        - 输入框输入
        - 点击前确认元素显示
        """
        return WebDriverWait(
            self.driver,
            timeout or self.timeout
        ).until(
            EC.visibility_of_element_located(locator)
        )

    def element_clickable(self, locator, timeout=None):
        """
        等待元素可点击
        使用场景：
        - Button 点击
        - 防止元素未加载完成导致点击失败
        """
        return WebDriverWait(
            self.driver,
            timeout or self.timeout
        ).until(
            EC.element_to_be_clickable(locator)
        )

    def element_present(self, locator, timeout=None):
        """
        等待元素存在
        注意：
        存在 ≠ 可见
        常用于：
        - 判断页面是否加载
        - 判断元素是否进入 DOM
        """
        return WebDriverWait(
            self.driver,
            timeout or self.timeout
        ).until(
            EC.presence_of_element_located(locator)
        )

    def element_disappear(self, locator, timeout=None):
        """
        等待元素消失
        使用场景：
        - Loading
        - 广告弹窗
        - 请求等待
        """
        return WebDriverWait(
            self.driver,
            timeout or self.timeout
        ).until(
            EC.invisibility_of_element_located(locator)
        )

    def toast_visible(self, text: str, timeout=5):
        """
        等待 Android Toast
        示例：
        登录成功
        密码错误
        """
        locator = (
            AppiumBy.XPATH,
            f'//android.widget.Toast[@text="{text}"]'
        )

        return WebDriverWait(
            self.driver,
            timeout
        ).until(
            EC.presence_of_element_located(locator)
        )

    def is_element_visible(self, locator, timeout=3) -> bool:
        """
        判断元素是否可见
        返回：
        True  元素存在且可见
        False 元素不存在或超时
        """
        try:
            self.element_visible(locator, timeout)
            return True
        except Exception:
            return False
```

### 3.1 等待 Activity 切换（App 专属）

登录成功后通常跳转到首页 Activity，用 Appium 原生能力等待：

```python title="testcases/test_login_wait.py"
# 方式一：expected_conditions（推荐，配合显式等待）
WebDriverWait(driver, 10).until(
    EC.activity_started("com.tal.kaoyan", "com.tal.kaoyan.ui.activity.HomeTabActivity")
)
# 方式二：driver 自带（阻塞式）
driver.wait_activity("com.tal.kaoyan.ui.activity.HomeTabActivity", timeout=10)
```

> [!note]
>
> 具体 Activity 名怎么拿？
> 手动操作到目标页，执行 `adb shell dumpsys window | findstr mCurrentFocus`（你已在 [[移动APP测试]] 用过）。

## 四、在用例中使用

```python title="testcases/test_login_wait.py"
import pytest
from appium.webdriver.common.appiumby import AppiumBy
from pages.base_page import BasePage


class TestLoginWait:
    def test_login_success_jumps_to_home(self, driver):
        base = BasePage(driver)
        # 登录按钮可点击后再点（显式等待兜底）
        login_btn = (AppiumBy.ID, "com.tal.kaoyan:id/login_login_btn")
        base.wait.element_clickable(login_btn, timeout=15).click()

        # 等待首页 Activity 出现（App 专属等待）
        from selenium.webdriver.support.ui import WebDriverWait
        from selenium.webdriver.support import expected_conditions as EC
        WebDriverWait(driver, 10).until(
            EC.activity_started("com.tal.kaoyan", "com.tal.kaoyan.ui.activity.HomeTabActivity")
        )
        print("✅ 登录成功，已跳转首页")
```

## 六、常见报错与排查点

| 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `TimeoutException` | 条件一直不满足 | ① 定位表达式错（回到 [[02-元素定位策略#一、AppiumBy 全家桶（对照 Selenium By）]] 核对）；② 页面真没跳（业务 bug？）；③ 超时设太短 |
| `StaleElementReferenceException` | 元素被重绘/页面刷新，旧引用失效 | 不要缓存 element 对象，每次操作前重新 `find`；或包一层显式等待 |
| 隐式+显式混用导致 "等很久" | 两者叠加 | `conftest.py` 里隐式只设小值（5s），业务全用显式 |
| Toast 抓不到 | Toast 几秒就消失 / XPath 没配对 | 用 `toast_visible()` 且 timeout 设 5s；文本要精确 |
| `activity_started` 报错 `not found` | expected_conditions 版本不支持该条件 | 旧版 Selenium 用 `driver.wait_activity(name, timeout)` 替代 |

> [!tip]
>
> flaky 用例的第一归因
> 移动端自动化 80% 的不稳定都源于 "等待没写好"。**任何 `NoSuchElement`/`TimeoutException` 先检查：是不是少了显式等待？** 不要靠 `sleep` 硬扛。
