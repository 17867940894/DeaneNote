## 一、为什么移动端更需要数据驱动

- **多账号矩阵**：正常/错误密码/空用户名/被封号/不同权限角色
- **多机型/多系统**：同一用例要在不同 `udid`、不同 Android 版本跑（用 `--params` 切环境）
- **用例膨胀**：10 个账号 × 手工复制 = 维护灾难；数据驱动 = 1 个脚本 + 1 张表

## 三、parametrize + YAML 驱动

```python title="testcases/test_data_driven.py"
"""
数据驱动登录用例
位置：testcases/test_data_driven.py
"""
import os
import pytest
import yaml
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.support.ui import WebDriverWait

from pages.home_page import HomePage
from pages.login_page import LoginPage


def load_cases():
    """从 YAML 读取测试数据"""
    path = os.path.join(os.path.dirname(__file__), "..", "data", "test_accounts.yaml")
    with open(path, encoding="utf-8") as f:
        return yaml.safe_load(f)


class TestDataDrivenLogin:
    @pytest.mark.parametrize("case", load_cases(), ids=lambda c: c["case"])
    def test_login(self, case, driver):
        login = LoginPage(driver).load()

        if case["expect"] == "error" and not (case["username"] and case["password"]):
            # 为空场景：App 前置校验把登录按钮灰置（不弹提示），
            # 分步填写后断言按钮不可点击，避免 login() 里 click 超时。
            login.fill_phone(case["username"])
            login.fill_code(case["password"])
            login.agree_protocol()
            assert not login.is_login_btn_enabled(), \
                "输入为空时登录按钮应不可点击（已实测 App 灰置按钮）"
            return

        login.login(case["username"], case["password"])

        if case["expect"] == "home":
            # 期望：跳转首页（等首页 Tab 元素；EC.activity_started 在 Python 不存在）
            WebDriverWait(driver, 10).until(
                EC.presence_of_element_located(HomePage.home_tab)
            )
            assert HomePage(driver).is_loaded()
        elif case["expect"] == "error":
            # 内容错误场景：登录失败 → 留在登录页。
            # 注：Toast 抓取（get_error_message）依赖 uiautomator2 事件流，不稳定，
            # 断言以"未跳转首页"为准；Toast 文案只打印不硬断言。
            assert not HomePage(driver).is_loaded(), "验证码错误不应跳转首页"
            print(f"  错误提示: {login.get_error_message()!r}")
        else:
            pytest.fail(f"未知的 expect: {case['expect']}")
```

### 运行与预期

```bash
pytest testcases/test_data_driven.py -v
```

```text
test_data_driven.py::TestDataDrivenLogin::test_login[正常登录] FAILED   ← 需真实验证码，外部依赖限制
test_data_driven.py::TestDataDrivenLogin::test_login[验证码错误] PASSED
test_data_driven.py::TestDataDrivenLogin::test_login[用户名为空] PASSED
test_data_driven.py::TestDataDrivenLogin::test_login[验证码为空] PASSED
===== 3 passed, 1 failed =====
```

> [!warning]
>
> **"正常登录"用例的真相（已实测）**：
> 考研帮是短信验证码登录，验证码无法在自动化里凭空生成（需短信平台/测试环境注入）。
> MuMu 模拟器收不到真实短信（`content://sms/inbox` 为空），所以 `expect: home` 这条在纯自动化下
> 必然失败——**不是代码问题，是外部依赖**。落地做法：
> ① 接短信平台/测试环境放行固定验证码；② 或只自动跑 `error` 场景（上面 3 条），登录成功用例留手工/单独环境。
> 另外，**错误 Toast 断言不可靠**：`get_error_message()` 依赖 uiautomator2 的事件流，
> 实测有的验证码值弹 Toast（如 `wrongpass`）、有的不弹（如全零 `000000`），
> 所以错误场景以"未跳转首页"为准，Toast 文案仅打印。

## 四、CSV 驱动（备选，Excel/测试同学友好）

如果不想用 YAML，可用 CSV（和 [[Selenium全栈笔记/02-进阶笔记/09-参数化与数据驱动#四、Excel 数据驱动（最常用）|Selenium 篇]] 的 Excel 思路一致）：

```python title="testcases/test_data_driven.py"
import csv, os

def load_cases_csv():
    path = os.path.join(os.path.dirname(__file__), "..", "data", "accounts.csv")
    with open(path, encoding="utf-8-sig") as f:
        return list(csv.DictReader(f))
```

`data/accounts.csv`：

```csv title="data/accounts.csv"
username,password,case,expect
13800000001,Test@123,正常登录,home
13800000001,wrongpass,密码错误,error
,Test@123,用户名为空,error
```

> [!tip] 
>
> 多环境/多设备矩阵
> 把 `udid`、Android 版本也写进数据表，用 `parametrize` 同时驱动"账号 × 设备"二维矩阵，是移动端兼容性测试的常用手法。

## 五、常见报错与排查点

| 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `yaml.YAMLError` | YAML 缩进/格式错 | 注意冒号后空格、列表 `-` 对齐；用 <https://www.yamllint.com/> 校验 |
| `FileNotFoundError: test_accounts.yaml` | 路径算错 | 用 `os.path.join(__file__, "..", "data", ...)` 相对路径，别写绝对路径 |
| 中文乱码 | 文件非 UTF-8 | 保存为 UTF-8；CSV 用 `utf-8-sig`（Excel 友好） |
| `ids=lambda` 报错 | pytest 版本差异 | 直接 `@pytest.mark.parametrize("case", load_cases())` 去掉 ids |
| 数据改了用例没变 | 缓存 / 没重跑 | 确认 pytest 重新收集；数据文件改动会被重新读取 |
| 某组用例失败但其他过 | 该组数据本身有问题 | 单独跑：`pytest testcases/test_data_driven.py -k "密码错误"` |
