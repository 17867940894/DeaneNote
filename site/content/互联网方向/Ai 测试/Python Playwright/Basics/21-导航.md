## 简介

Playwright 可以导航到 URL 并处理由页面交互引起的导航。

## 基本导航

最简单的导航形式是打开 URL


```py
# Navigate the page
page.goto("https://example.com")
```

上述代码会加载页面并等待网页触发 [load](https://mdn.org.cn/en-US/docs/Web/API/Window/load_event) 事件。当整个页面加载完成（包括所有依赖资源，如样式表、脚本、iframe 和图片）时，会触发 load 事件。


> [!caution]
>
> 如果页面在 `load` 触发之前进行客户端重定向，[page.goto()](https://playwright.cn/python/docs/api/class-page#page-goto) 将等待重定向后的页面触发 `load` 事件。

## 页面何时加载完成？

现代页面在 `load` 事件触发后会执行许多活动。它们会延迟加载数据、填充 UI、在 `load` 事件触发后加载昂贵的资源、脚本和样式。没有一种方法可以确定页面已“完全加载”（`loaded`），这取决于页面、框架等。那么，你何时可以开始与它交互呢？

在 Playwright 中，你可以在任何时刻与页面进行交互。它会自动等待目标元素变为[可操作](https://playwright.cn/python/docs/actionability)。


```py
# Navigate and click element
# Click will auto-wait for the element

page.goto("https://example.com")
page.get_by_text("example domain").click()
```

对于上述情况，Playwright 将等待文本变得可见，等待该元素的其余可操作性检查通过，然后点击它。

Playwright 的操作速度非常快——它一看到按钮，就会点击它。通常情况下，您无需担心所有资源是否已加载等问题。

## 水合 (Hydration)

在某些情况下，您可能会遇到这样的用例：Playwright 执行了操作，但看起来什么也没发生；或者您在输入框中输入了一些文本，但随后文本消失了。造成这种情况最可能的原因是页面[水合 (hydration)](https://en.wikipedia.org/wiki/Hydration_(web_development)) 不完善。

当页面进行水合时，首先会将页面的静态版本发送到浏览器。然后发送动态部分，页面变为“实时”。作为一个非常快的用户，Playwright 会在看到页面的那一刻开始与之交互。如果页面上的按钮已启用，但监听器尚未添加，Playwright 会完成它的工作，但点击将不会有任何效果。

验证你的页面是否存在水合不佳问题的简单方法是打开 Chrome 开发者工具，在“网络”面板中选择“慢速 3G”网络模拟，然后重新加载页面。一旦看到你感兴趣的元素，就与之交互。你会发现按钮点击会被忽略，输入的文本会在后续的页面加载代码中被重置。解决此问题的正确方法是确保所有交互式控件在水合完成、页面完全功能化之前都处于禁用状态。

## 等待导航

点击元素可能会触发多次导航。在这种情况下，建议显式使用 [page.wait_for_url()](https://playwright.cn/python/docs/api/class-page#page-wait-for-url) 指向特定的 url。


```py
page.get_by_text("Click me").click()
page.wait_for_url("**/login")
```

## 往返缓存 (BFCache)

现代浏览器利用往返缓存 (BFCache) 在用户点击后退或前进时立即加载页面。这是通过将页面的 DOM 和 JavaScript 堆在内存中冻结，并在返回时将其解冻来实现的。

默认情况下，Playwright 会在所有浏览器中禁用 BFCache，以确保测试环境的一致性和纯净。

即使你显式启用 BFCache，**也不支持测试 BFCache 的恢复**。由于 BFCache 恢复会跳过网络获取阶段，浏览器不会触发标准的导航生命周期事件（例如 `commit`、`domcontentloaded` 或 `load`）。Playwright 的内部 `Page` 状态严重依赖这些网络级事件来保持同步。

因此，触发 BFCache 恢复（例如通过 `page.goBack()`）将绕过 Playwright 的生命周期跟踪，导致超时以及一个完全不同步的 `Page` 对象，从而使后续的交互失败。

## 导航事件

Playwright 将在页面中显示新文档的过程分为**导航**和**加载**。

**导航开始**通过更改页面 URL 或与页面交互（例如，点击链接）。导航意图可能会被取消，例如，在遇到未解析的 DNS 地址或转换为文件下载时。

当响应头被解析并且会话历史记录更新后，**导航被提交**。只有在导航成功（已提交）后，页面才开始**加载**文档。

**加载**包括通过网络获取剩余的响应体、解析、执行脚本和触发加载事件

- [page.url](https://playwright.cn/python/docs/api/class-page#page-url) 被设置为新的 url
- 文档内容通过网络加载并解析
- [page.on("domcontentloaded")](https://playwright.cn/python/docs/api/class-page#page-event-dom-content-loaded) 事件被触发
- 页面执行一些脚本并加载样式表和图片等资源
- [page.on("load")](https://playwright.cn/python/docs/api/class-page#page-event-load) 事件被触发
- 页面执行动态加载的脚本
