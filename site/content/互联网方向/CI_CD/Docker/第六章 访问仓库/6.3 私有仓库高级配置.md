# 6.3 私有仓库高级配置

> **来源**：Docker 入门教程


## 一、概述

上一节搭建了一个具有基础功能的私有仓库，本节使用 **Docker Compose** 搭建一个拥有**权限认证**和 **TLS** 的私有仓库。

> **版本说明**：本节示例沿用了 Distribution v2.x 兼容路径；新生产部署应评估 Distribution 3.x，并核对配置路径、迁移说明和生态兼容性。


## 二、准备站点证书

假设私有仓库地址为 `docker.domain.com`，下面介绍使用 `openssl` 自行签发站点 SSL 证书。

### 2.1 创建 CA 根证书

**第一步：创建 CA 私钥**

```bash
openssl genrsa -out "root-ca.key" 4096
```

**第二步：创建 CA 根证书请求文件**

```bash
$ openssl req \
    -new -key "root-ca.key" \
    -out "root-ca.csr" -sha256 \
    -subj '/C=CN/ST=Shanxi/L=Datong/O=Your Company Name/CN=Your Company Name Docker Registry CA'
```

> 参数说明：`/C`=国家，`/ST`=省，`/L`=城市/地区，`/O`=组织名，`/CN`=通用名称。

**第三步：配置 CA 根证书**，新建 `root-ca.cnf`

```ini
[root_ca]
basicConstraints = critical,CA:TRUE,pathlen:1
keyUsage = critical, nonRepudiation, cRLSign, keyCertSign
subjectKeyIdentifier=hash
```

**第四步：签发根证书**

```bash
$ openssl x509 -req -days 3650 -in "root-ca.csr" \
    -signkey "root-ca.key" -sha256 -out "root-ca.crt" \
    -extfile "root-ca.cnf" -extensions root_ca
```

### 2.2 生成站点 SSL 证书

**第五步：生成站点 SSL 私钥**

```bash
openssl genrsa -out "docker.domain.com.key" 4096
```

**第六步：生成证书请求文件**

```bash
$ openssl req -new -key "docker.domain.com.key" -out "site.csr" -sha256 \
    -subj '/C=CN/ST=Shanxi/L=Datong/O=Your Company Name/CN=docker.domain.com'
```

**第七步：配置证书**，新建 `site.cnf`

```ini
[server]
authorityKeyIdentifier=keyid,issuer
basicConstraints = critical,CA:FALSE
extendedKeyUsage=serverAuth
keyUsage = critical, digitalSignature, keyEncipherment
subjectAltName = DNS:docker.domain.com, IP:127.0.0.1
subjectKeyIdentifier=hash
```

**第八步：签署站点 SSL 证书**

```bash
$ openssl x509 -req -days 750 -in "site.csr" -sha256 \
    -CA "root-ca.crt" -CAkey "root-ca.key" -CAcreateserial \
    -out "docker.domain.com.crt" -extfile "site.cnf" -extensions server
```

### 2.3 整理证书文件

新建 `ssl` 文件夹，将以下三个文件移入，删除其他文件：

- `docker.domain.com.key`（站点私钥）
- `docker.domain.com.crt`（站点证书）
- `root-ca.crt`（CA 根证书）

> **安全提示**：私钥和证书应在本地或受控部署环境中生成，**不要提交进 Git 仓库**。


## 三、配置私有仓库

私有仓库默认配置文件位于 `/etc/docker/registry/config.yml`，在本地编辑后挂载到容器中。

```yaml
log:
  accesslog:
    disabled: true
  level: debug
  formatter: text
  fields:
    service: registry
    environment: staging

storage:
  delete:
    enabled: true
  cache:
    blobdescriptor: inmemory
  filesystem:
    rootdirectory: /var/lib/registry

auth:
  htpasswd:
    realm: basic-realm
    path: /etc/docker/registry/auth/nginx.htpasswd

http:
  addr: :5000
  host: https://docker.domain.com
  headers:
    X-Content-Type-Options: [nosniff]
  http2:
    disabled: false
  tls:
    certificate: /etc/docker/registry/ssl/docker.domain.com.crt
    key: /etc/docker/registry/ssl/docker.domain.com.key

health:
  storagedriver:
    enabled: true
    interval: 10s
    threshold: 3
```


## 四、生成 HTTP 认证文件

```bash
$ mkdir auth

$ docker run --rm \
    --entrypoint htpasswd \
    httpd:2.4-alpine \
    -Bbn username password > auth/nginx.htpasswd
```

> 将 `username` 和 `password` 替换为自己的用户名和密码。
>
> **安全提示**：上述命令会将密码明文暴露在 shell 历史记录中。生产环境建议使用交互式方式（不带 `-b` 参数），或通过环境变量/文件传入。


## 五、编辑 Docker Compose 配置

编辑 `compose.yaml`（或 `docker-compose.yml`）：

```yaml
services:
  registry:
    image: registry:2
    ports:
      - "443:5000"
    volumes:
      - ./:/etc/docker/registry
      - registry-data:/var/lib/registry

volumes:
  registry-data:
```

> **版本说明**：
>
> - 明确指定 `registry:2` 版本，生产环境建议固定具体补丁版本（如 `registry:2.8.x`）
> - 容器内 registry 监听 `:5000`，宿主机通过 `443:5000` 暴露 HTTPS 服务


## 六、修改 Hosts 文件

编辑 `/etc/hosts`：

```text
127.0.0.1 docker.domain.com
```


## 七、启动

```bash
docker compose up -d
```


## 八、测试私有仓库功能

### 8.1 安装 CA 根证书

由于自行签发的 CA 根证书不被系统信任，需要将其移入 Docker 证书目录：

```bash
sudo mkdir -p /etc/docker/certs.d/docker.domain.com
sudo cp ssl/root-ca.crt /etc/docker/certs.d/docker.domain.com/ca.crt
```

### 8.2 登录并测试

```bash
# 登录私有仓库
$ docker login docker.domain.com

# 拉取基础镜像并打标签
$ docker pull ubuntu:24.04
$ docker tag ubuntu:24.04 docker.domain.com/username/ubuntu:24.04

# 推送镜像
$ docker push docker.domain.com/username/ubuntu:24.04

# 删除本地镜像并重新拉取验证
$ docker image rm docker.domain.com/username/ubuntu:24.04
$ docker pull docker.domain.com/username/ubuntu:24.04
```

### 8.3 验证权限认证

退出登录后尝试推送：

```bash
$ docker logout docker.domain.com
$ docker push docker.domain.com/username/ubuntu:24.04

no basic auth credentials
```

发现提示没有登录，无法推送到私有仓库，说明权限认证生效。


## 九、注意事项

- 如果本机占用了 `443` 端口，可以配置 [Nginx 代理](https://distribution.github.io/distribution/recipes/nginx/) 转发
- 生产环境建议使用受信任的 CA 签发的证书，而非自签名证书
- **安全提示**：所有私钥（`.key` 文件）和 `nginx.htpasswd` 文件不应提交到 Git 仓库
