# 第六章：Docker 仓库（Repository）

> **来源**：Docker 入门教程


## 一、核心概念

**仓库（Repository）** 是集中存放镜像的地方。

### 1.1 仓库 vs 注册服务器（Registry）

| 概念 | 说明 | 示例 |
|---|---|---|
| **Registry（注册服务器）** | 管理仓库的具体服务器 | `docker.io` |
| **Repository（仓库）** | 服务器上的具体项目或目录 | `ubuntu` |
| **完整地址** | Registry + Repository | `docker.io/ubuntu` |

> 💡 大部分时候，并不需要严格区分这两者的概念。


## 二、版本号说明

本章涉及的 Registry 和相关工具版本说明：

| 组件 | 版本建议 | 说明 |
|---|---|---|
| **Docker Registry / CNCF Distribution** | `registry:2`（兼容路径） | 新生产部署应评估 Distribution 3.x；已停止维护的 `registry:1` 不建议使用 |
| **Nexus 3** | 指定具体版本（如 `sonatype/nexus3:3.69`） | 避免 `latest` 自动升级带来的兼容性问题 |

### 镜像标签规范

- 生产环境应明确指定版本号（如 `myapp:v1.0.0`）
- 避免依赖 `latest` 标签，因其含义存在歧义且易导致版本混淆


## 三、为什么需要私有仓库？

| 场景 | 建议 | 方案 |
|---|---|---|
| **开发团队**（有专利代码、不能公开） | 需要私有仓库存储内部镜像，涉及访问控制和审计 | 强烈推荐托管方案（Harbor 或云厂商镜像仓库） |
| **开源项目/个人学习** | Docker Hub 公开仓库足够 | 无需自建私有仓库 |
| **企业级部署** | 需要高可用、备份、灾难恢复 | 推荐专业级方案（Nexus 3、Harbor）而非简单 Registry |

### 方案选择建议

| 方案 | 适用场景 | 特点 |
|---|---|---|
| **Docker Hub** | 开源项目、个人学习 | 免费公开仓库，无需自建 |
| **Docker Registry** | 简单私有场景 | 最小化部署，功能基础 |
| **Registry + 认证/HTTPS** | 生产环境私有仓库 | 添加安全配置 |
| **Nexus 3 / Harbor** | 企业级部署 | 权限管理、备份、高可用 |


## 五、常用命令速查

| 命令 | 说明 |
|---|---|
| `docker login` | 登录 Registry |
| `docker logout` | 登出 Registry |
| `docker pull <镜像名>` | 从仓库拉取镜像 |
| `docker push <镜像名>` | 推送镜像到仓库 |
| `docker tag <镜像> <仓库名:标签>` | 为镜像打标签 |
| `docker search <关键词>` | 在 Docker Hub 搜索镜像 |
| `docker image ls` | 查看本地镜像列表 |
