### 1. Linux下查看日志的命令及特点？

- **`tail`**：最常用，默认显示文件末尾10行。**特点**：支持 `-f` 实时追踪日志更新（排查线上问题首选）。

- **`head`**：显示文件开头部分，适合查看日志头部信息。

- **`cat`**：一次性输出整个文件。**特点**：常结合 `grep` 过滤关键词，但文件过大易卡顿。

- **`less`**：分页查看，支持上下翻页和 `/关键词` 搜索。**特点**：不会一次性加载全文件，大日志文件首选。

- **`more`**：类似less，但只能向下翻页，功能较单一。

- **`grep`**：文本过滤，常配合管道符（如 `cat log | grep "ERROR"`），**特点**：支持正则匹配，精准提取异常行。

- **`sed/awk`**：强大的文本处理工具，适用于截取特定时间段或格式化的日志分析。

### 2. URL的可能组成部分？

标准格式：`协议://用户名:密码@主机名:端口号/路径?查询参数#锚点`

- **协议（Scheme）**：如 `http`、`https`、`ftp`。

- **认证信息（Userinfo）**：`username:password@`，可选。

- **主机名（Host）**：域名或IP地址。

- **端口号（Port）**：如 `:8080`，HTTP默认80，HTTPS默认443可省略。

- **路径（Path）**：资源在服务器上的具体位置，如 `/api/v1/user`。

- **查询参数（Query）**：`?key1=value1&key2=value2`，用于传递动态数据。

- **锚点（Fragment）**：`#top`，页面内定位，不发送给服务端。

### 3. 测试报告中有遗留缺陷，可以上线吗？

**答案不是绝对的“能”或“不能”**，需综合评估：

- **可以上线的情况**：遗留缺陷为**建议级**或**界面轻微错位**等低优先级问题；或存在**临时规避方案**（如重启可恢复）；且**业务方、产品经理、开发、测试**四方达成共识并签字确认，明确修复时间表。

- **绝对不可以上线的情况**：遗留缺陷为**致命/严重级别**（如系统崩溃、资金计算错误、核心流程阻塞、存在安全漏洞）。

- **核心原则**：**风险可控**。必须输出《遗留缺陷风险评估报告》，明确告知上线风险，绝不能未经评估擅自上线。

### **4. Bug的状态有哪些？**（通用标准流程）

- **New（新建）**：测试刚提交，待确认。

- **Open/Assigned（打开/已分配）**：开发确认是Bug，正在处理。

- **Fixed（已修复）**：开发已改完代码，等待测试验证。

- **Verified（已验证）**：测试复测通过，确认已修复。

- **Closed（已关闭）**：验证通过且已上线，Bug生命周期结束。

- **Reopen（重新打开）**：修复后验证仍不通过，或上线后问题复现。

- **Rejected（已拒绝）**：开发认为是需求理解偏差、重复Bug或无法复现，退回给测试。

- **Deferred（延期）**：优先级极低，当前版本不修，排期到后续版本。

### 1. 常用的 ADB 命令有哪些？

ADB（Android Debug Bridge）是安卓调试的基石，以下是最实用的分类命令：

**基础连接与设备**

- `adb devices`：列出已连接的设备列表（最常用，用于确认设备在线）。
- `adb connect <IP:端口>`：连接远程无线调试设备（如 `adb connect 192.168.1.100:5555`）。
- `adb disconnect <IP:端口>`：断开无线连接。
- `adb root`：获取 root 权限（用于更高权限的操作）。
- `adb kill-server` / `adb start-server`：重启 ADB 服务（解决设备离线问题）。

**应用管理**

- `adb install -r <APK路径>`：安装 APK（`-r` 表示覆盖安装）。
- `adb uninstall <包名>`：卸载应用（如 `adb uninstall com.example.app`）。
- `adb shell pm list packages`：列出所有已安装的包名（配合 `grep` 过滤）。

**系统交互与调试**

- `adb shell`：进入设备的 Linux shell 环境。
- `adb shell dumpsys <服务名>`：获取系统服务详情（如 `adb shell dumpsys battery` 查看电池，`adb shell dumpsys meminfo <包名>` 查看内存）。
- `adb logcat`：查看实时日志（常用 `adb logcat -v time` 带时间戳，`adb logcat -c` 清空缓存）。
- `adb shell screencap /sdcard/screen.png`：截图（配合 `adb pull` 导出）。
- `adb shell input tap <x> <y>` / `input swipe`：模拟点击和滑动。

**文件操作**

- `adb push <本地路径> <设备路径>`：推送文件到设备。
- `adb pull <设备路径> <本地路径>`：从设备拉取文件。

### 2. GET 请求和 POST 的区别？

从原理和应用层面看，核心区别如下：

| 维度         | GET                                             | POST                                    |
| ---------- | ----------------------------------------------- | --------------------------------------- |
| **语义**     | 获取资源（只读操作，幂等）                                   | 提交/创建资源（非幂等，可能改变服务器状态）                  |
| **数据传输位置** | 参数附在 **URL 末尾**（`?key1=value1&key2=value2`）     | 参数放在 **请求体（Body）** 中                    |
| **数据长度限制** | 受 URL 长度限制（浏览器约 2K，服务器可配置）                      | 无理论限制（取决于服务器配置）                         |
| **缓存**     | 可被浏览器/代理服务器缓存                                   | 默认不缓存（可手动控制）                            |
| **书签/历史**  | 可被收藏，参数会保留在历史记录                                 | 不会被收藏，历史中不保留 Body                       |
| **安全性**    | 参数暴露在地址栏，易被浏览器历史/服务器日志记录                        | 相对更安全（但 HTTPS 是前提，Body 在 HTTP 明文下同样不安全） |
| **编码类型**   | 仅支持 URL 编码（`application/x-www-form-urlencoded`） | 支持多种编码（表单、JSON、Multipart 等）             |

**关键认知纠正**：很多人误以为“GET 有长度限制，POST 安全”，但在 RESTful 规范中，**GET 用于查询，POST 用于新增**才是本质区别。同时，POST 并不比 GET 更“安全”，真正的安全依赖 HTTPS。

### 3. HTTP 协议的响应码是如何定义的？

HTTP 状态码由 **RFC 标准**定义，分为 5 大类（首位数字代表类别）：

| 分类                  | 范围    | 含义                   | 典型举例                                                     |
| --------------------- | ------- | ---------------------- | ------------------------------------------------------------ |
| **1xx（信息）**       | 100-199 | 请求已接收，继续处理   | `100 Continue`（客户端应继续请求）                           |
| **2xx（成功）**       | 200-299 | 请求成功处理           | `200 OK`（标准成功）<br>`201 Created`（POST 创建成功）<br>`204 No Content`（成功但无返回体） |
| **3xx（重定向）**     | 300-399 | 需进一步操作以完成请求 | `301 Moved Permanently`（永久重定向）<br>`302 Found`（临时重定向）<br>`304 Not Modified`（缓存未变更） |
| **4xx（客户端错误）** | 400-499 | 请求有误，责任在客户端 | `400 Bad Request`（语法错误）<br>`401 Unauthorized`（未认证）<br>`403 Forbidden`（无权限）<br>`404 Not Found`（资源不存在）<br>`429 Too Many Requests`（限流） |
| **5xx（服务端错误）** | 500-599 | 服务器处理失败         | `500 Internal Server Error`（服务器内部错误）<br>`502 Bad Gateway`（网关错误）<br>`503 Service Unavailable`（服务不可用）<br>`504 Gateway Timeout`（网关超时） |

**补充**：实际测试中需重点关注 **4xx** 和 **5xx**，前者暴露接口设计问题，后者暴露后端稳定性问题。

### 4. 静态测试和动态测试的区别？

这是软件测试中两种最基本的策略，区别如下：

| 维度             | 静态测试                                                     | 动态测试                                     |
| ---------------- | ------------------------------------------------------------ | -------------------------------------------- |
| **执行代码**     | **不运行**被测软件                                           | **必须运行**被测软件                         |
| **测试对象**     | 文档、源代码、设计图、需求规格                               | 可执行程序、系统                             |
| **手段**         | 人工评审（走查/审查）+ 静态分析工具（如 SonarQube、FindBugs） | 执行测试用例，输入数据，观察输出和运行行为   |
| **发现缺陷类型** | 逻辑错误、编码规范、设计缺陷、文档不一致                     | 运行时错误（崩溃、性能、内存泄漏、功能不符） |
| **何时介入**     | **尽早**（需求阶段、编码阶段）                               | **较晚**（编码完成、构建成功后）             |
| **成本**         | 低成本，早期发现可节省数倍修复成本                           | 成本较高（需环境、数据、执行时间）           |

**经典比喻**：静态测试像“医生查看体检报告单”（分析文本），动态测试像“给病人做运动心电图”（实际运行观察反应）。

### 4. Python中实现对数字的截取和四舍五入，用哪个命令？详细说明？

主要通过以下函数实现：

#### ① `round()` — 四舍五入

```python
round(number, ndigits=None)
```

| 参数      | 说明                          |
| --------- | ----------------------------- |
| `number`  | 要处理的数字（整数或浮点数）  |
| `ndigits` | 保留的小数位数（可选，默认0） |

**示例：**

```python
round(3.14159, 2)      # 3.14
round(3.14159, 0)      # 3.0
round(3.14159)         # 3（ndigits默认0）
round(2.675, 2)        # 2.67 ⚠️ 注意：浮点数精度问题！
round(2.5)             # 2  ⚠️ Python银行家舍入（向偶数取整）
round(3.5)             # 4
```

> ⚠️ **注意**：`round()` 使用 **"银行家舍入"**（四舍六入五成双），并非数学上的四舍五入。对于精确的财务计算，建议用 `decimal.Decimal`。

---

#### ② 数字截取（取整/截断）

| 方法           | 功能                         | 示例                                           |
| -------------- | ---------------------------- | ---------------------------------------------- |
| `int()`        | 直接截断小数部分（向零取整） | `int(3.9) → 3`，`int(-3.9) → -3`               |
| `math.floor()` | 向下取整（≤原数的最大整数）  | `math.floor(3.9) → 3`，`math.floor(-3.9) → -4` |
| `math.ceil()`  | 向上取整（≥原数的最小整数）  | `math.ceil(3.1) → 4`，`math.ceil(-3.1) → -3`   |
| `math.trunc()` | 截断小数部分（同int）        | `math.trunc(3.9) → 3`                          |

**示例：**

```python
import math

# 截取小数部分（取整）
int(3.14159)          # 3
math.floor(3.14159)   # 3
math.ceil(3.14159)    # 4
math.trunc(3.14159)   # 3

# 截取指定位数（通过运算实现）
def truncate(num, digits):
    factor = 10 ** digits
    return math.trunc(num * factor) / factor

truncate(3.14159, 2)  # 3.14
truncate(3.14159, 3)  # 3.141
```

---

#### ③ 格式化输出（四舍五入+显示）

```python
# 字符串格式化（会四舍五入）
f"{3.14159:.2f}"      # '3.14'
"{:.3f}".format(3.14159)  # '3.142'
```

---

#### 📌 总结建议

| 需求                     | 推荐方法                              |
| ------------------------ | ------------------------------------- |
| **普通四舍五入**         | `round()`（注意银行家舍入问题）       |
| **数学四舍五入（精确）** | 使用 `decimal.Decimal` + `quantize()` |
| **向下截取指定位数**     | 自定义 `truncate()` 函数              |
| **直接取整截断**         | `int()` 或 `math.trunc()`             |
| **向下/向上取整**        | `math.floor()` / `math.ceil()`        |
| **仅显示用**             | f-string 或 `format()`                |

如果需要精确的四舍五入（如财务场景），推荐使用 `decimal` 模块：

```python
from decimal import Decimal, ROUND_HALF_UP
Decimal('2.675').quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)  # 2.68
```

### 1. 列表 list 与元组 tuple 的核心区别及适用场景

| 对比维度     | **列表 list**                | **元组 tuple**                                               |
| ------------ | ---------------------------- | ------------------------------------------------------------ |
| **可变性**   | **可变**（可增删改元素）     | **不可变**（创建后不能修改）                                 |
| **内存占用** | 较大（预留额外空间用于扩容） | 较小（固定大小，内存紧凑）                                   |
| **性能**     | 稍慢（有动态扩容开销）       | 更快（创建和访问都更高效）                                   |
| **哈希性**   | 不可哈希（不能作为字典键）   | 可哈希（可作为字典键或集合元素，**前提**：内部元素也都是可哈希的） |

**适用场景**：

- **列表（list）适用**：
  - 元素数量动态变化（如追加、删除、插入）
  - 需要批量修改数据（如排序、反转）
  - 常见案例：用户输入列表、待处理任务队列、从文件读取的多行数据

- **元组（tuple）适用**：
  - 数据**不需要修改**且代表**固定结构**（如坐标 (x, y)、RGB 颜色值、[[16-数据库]]一行记录）
  - 作为字典的键或集合的元素
  - 函数返回多个值时（本质是元组拆包）
  - 作为函数的**默认参数**（避免可变对象被意外修改的陷阱）

```python
# 列表典型用法
users = ["Alice", "Bob"]
users.append("Charlie")   # 动态添加

# 元组典型用法
RGB_RED = (255, 0, 0)     # 常量，固定结构
config = {"host": "localhost", "port": 8080, "timeout": (3, 5)}  # 作为字典值
```

### 2. break 和 continue 的作用及在 if 中的使用

| 关键字       | 作用                                                        | 能否在 if 中单独使用？               |
| ------------ | ----------------------------------------------------------- | ------------------------------------ |
| **break**    | **终止**当前所在的最内层循环（`for` / `while`），跳出循环体 | ❌ **不能**单独使用，必须嵌套在循环内 |
| **continue** | **跳过**本次循环剩余代码，立即进入下一次循环迭代            | ❌ **不能**单独使用，必须嵌套在循环内 |

**关键理解**：

- `break` 和 `continue` 是**循环控制语句**，它们只对循环（`for` / `while`）起作用。
- 它们可以**写在 `if` 语句内部**，但前提是这个 `if` 必须位于循环体中。`if` 只是执行条件判断，真正执行跳转的还是 `break`/`continue`。

```python
# ✅ 正确：break/continue 在循环内的 if 中
for i in range(10):
    if i == 5:
        break          # 终止循环
    if i % 2 == 0:
        continue       # 跳过偶数

# ❌ 错误：break 不在循环内
if True:
    break   # SyntaxError: 'break' outside loop
```

### 3. for 循环与 while 循环的适用场景

| 循环类型                               | 适用场景                                                     | 典型案例                                                     |
| -------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **`for` 循环**（**迭代次数明确**）     | 遍历**可迭代对象**（列表、元组、字符串、字典、生成器等）；已知循环次数；或需要处理序列中的每个元素 | `for item in list:` 遍历数据；`for i in range(n):` 执行 n 次；`for k, v in dict.items():` 遍历字典 |
| **`while` 循环**（**迭代次数不明确**） | 基于**条件判断**控制循环，适合循环次数未知、依赖外部状态或需要无限循环的场景 | `while True:` 事件循环（如服务器监听）；`while data != "quit":` 用户输入控制；`while index < len(list):` 手动索引遍历 |

**经验法则**：

- **优先用 `for`**：只要你能明确需要遍历什么，就选 `for`，它更简洁、更安全（自动处理边界）。
- **用 `while` 的场景**：你需要**在循环内部动态改变循环条件**，或者循环次数完全由运行时状态决定。

```python
# for：处理固定数据
for file in files:
    process(file)

# while：等待条件满足
response = None
while response is None:
    response = get_data()   # 直到获取到数据才退出
```

| 方法           | 删除方式         | 参数                                            | 返回值           | 说明                                                        |
| -------------- | ---------------- | ----------------------------------------------- | ---------------- | ----------------------------------------------------------- |
| **`pop()`**    | 按**索引**删除   | 可选参数 `index`（默认为 `-1`，即最后一个元素） | 返回被删除的元素 | 如果指定索引越界，抛出 `IndexError`                         |

### 1. 什么是继承？继承有什么作用？子类重写父类同名方法时执行规则是什么？

#### （1）继承定义

继承是面向对象中，**子类可以复用父类已有的属性和方法**的机制，语法：`class 子类(父类):`。父类也叫基类，子类也叫派生类。

#### （2）继承作用

1. 代码复用：不用重复编写相同功能，减少冗余代码；
2. 代码扩展：子类在父类基础上新增、修改功能；
3. 建立类与类之间层级关系，便于程序分层管理。

#### （3）子类重写同名方法执行规则

1. 子类和父类存在同名方法时，**优先执行子类自身重写后的方法**；
2. 若需要调用父类原本被覆盖的方法，使用 `super().方法名()`；
3. 执行顺序：先执行子类重写逻辑，若写了 super 则先执行父类方法，再执行子类新增逻辑。

------

### 2. __init__方法是什么？super ().**init**() 在子类构造方法中的作用是什么？

#### （1）`__init__` 构造方法

1. 是 Python 内置特殊方法，称为**构造函数**；
2. 创建类实例（对象）时会**自动调用**；
3. 作用：初始化实例的数据成员（给 self 绑定属性，给对象赋初始值）。

#### （2）`super().__init__()` 作用

1. 在子类构造函数中，主动调用父类的构造方法；
2. 让子类实例自动继承、初始化父类中定义的实例属性；
3. 如果父类有必须初始化的参数，不加这句会导致父类属性缺失、程序报错。

------

### 3. self 关键字的作用是什么？能否在类外部直接使用 self？为什么？

#### （1）self 作用

1. self 是实例方法第一个固定参数，**代表当前调用方法的实例对象本身**；
2. 通过`self.属性名`定义 / 访问实例数据成员；
3. 通过`self.方法名()`调用本类其他实例方法；
4. 区分实例变量和局部变量。

#### （2）不能在类外部直接使用 self

原因：

1. self 不是关键字，只是约定俗成的普通参数名；
2. self 只有在实例方法被对象调用时，才会自动接收当前实例；
3. 类外部没有实例对象传入，没有任何对象可以绑定给 self，直接使用会报未定义变量错误。

------

### 4. 面向对象三大特性：封装、继承、多态

#### 1）封装

1. 将一类事物的**数据（属性）** 和**操作数据的方法**打包放在一个类中；
2. 隐藏内部实现细节，对外只暴露简单访问接口；
3. 控制数据访问权限（下划线区分公有 / 保护 / 私有），提高代码安全性。

#### 2）继承

子类获取父类全部公有属性与方法，实现代码复用，在父类基础上拓展新功能，构建类的层级体系。

#### 3）多态

同一个方法，不同子类对象调用会表现出不同执行效果；

核心：父类引用指向子类对象，子类重写同名方法，调用时自动执行子类逻辑，提高程序扩展性。

### 精简背诵版（课堂口述专用，简短好记）

1. **继承**：子类复用父类属性方法；作用：复用代码、方便扩展；重写规则：优先执行子类方法，super 可调用父类原方法。

2. ***\*init\****：构造方法，创建对象自动执行，初始化属性；super ().**init**()：调用父类构造，初始化父类继承的属性。

3. **self**：代表当前实例对象，操作实例属性方法；外部不能用，self 依赖实例调用传参，外部无实例。

4. **三大特性**


   封装：属性方法打包，隐藏内部细节；


   继承：子类复用父类代码；


   多态：同一方法，不同子类对象执行不同逻辑。

`split()` 是Python字符串（`str`）的一个内置方法，用于**将字符串按照指定的分隔符切割成一个列表**（List）。

**不传入分隔符时：**  
`split()` 方法会采用**默认行为**，即：

- 以**任意空白字符（whitespace）** 作为分隔符，包括**空格**、**制表符（`\t`）**、**换行符（`\n`）**等。
- 自动忽略**连续的空白字符**，并将它们视为一个分隔符。
- 自动**去除结果列表开头和结尾的空字符串**（即不会返回空元素）。

**示例对比：**

```python
# 传入特定分隔符
s1 = "apple,banana,orange"
print(s1.split(','))
# 输出: ['apple', 'banana', 'orange']

# 不传入分隔符（处理多种空白）
s2 = "hello   world\t\ngoodbye"
print(s2.split())
# 输出: ['hello', 'world', 'goodbye']   （注意多个空格和\t都被视为一个分隔符）

# 不传入分隔符 vs 传入空格的区别
s3 = " a b c "
print(s3.split(' '))   # 传入单个空格：['', 'a', 'b', 'c', '']  （保留首尾空元素）
print(s3.split())      # 不传参：['a', 'b', 'c']  （自动过滤首尾空格）
```

1. **Number**：整数和浮点数（包括 `Infinity`、`NaN`）。
2. **String**：文本字符串（单引号/双引号/反引号模板字符串）。
3. **Boolean**：逻辑值，只有 `true` 和 `false`。
4. **Undefined**：声明了变量但未赋值时的默认值。
5. **Null**：表示“空”或“不存在”的对象占位符。
6. **Symbol**（ES6引入）：表示独一无二的值，常用于对象属性的唯一键。
7. **BigInt**（ES2020引入）：用于表示超出 Number 安全范围的大整数。

**引用数据类型（1种）：**

- **Object（对象）**：包括普通对象 `{}`、数组 `[]`、函数 `function`、日期 `Date`、正则 `RegExp` 等。**核心区别**：基本类型存“值”，引用类型存“内存地址（指针）”。

### 2. Postman断言中，常见的判断有哪些？（简述5个）

- **状态码断言**（`pm.response.to.have.status(200)`）：验证HTTP响应状态码是否符合预期。
- **响应体断言**（`pm.response.to.have.jsonBody("key", value)`）：验证返回的JSON体中特定字段的值是否正确。
- **响应头断言**（`pm.response.to.have.header("Content-Type", "application/json")`）：检查响应头中的特定键值对是否存在。
- **响应体包含文本**（`pm.expect(pm.response.text()).to.include("success")`）：检查原始响应体中是否包含指定的字符串。
- **响应时间断言**（`pm.expect(pm.response.responseTime).to.be.below(200)`）：验证接口响应耗时是否小于设定的阈值（如200ms），用于性能基线测试。

### 3. 变量类型有哪些？（名称及含义）

- **全局变量（Global）**：作用域最大，跨所有集合、环境和请求，生命周期长，通常存放通用的固定值（如Base URL）。
- **环境变量（Environment）**：针对特定环境（开发/测试/生产），切换环境时变量值自动切换，常用于区分不同环境的域名或账号。
- **集合变量（Collection）**：作用域仅限当前集合内的所有请求，常用于传递该集合特有的认证Token或ID。
- **数据变量（Data）**：来源于数据文件（CSV/JSON），只在迭代运行集合时生效，用于参数化驱动测试。
- **局部变量（Local）**：在脚本中临时声明的变量（如 `let temp = ...`），仅在当前请求的脚本执行期间有效。

### 第1题：正交实验法的操作流程？

正交实验法核心是**用最少的实验次数，覆盖最多的因素组合**，特别适合多因素多水平的配置类测试（如浏览器兼容性）。

**标准操作流程（6步）：**

1. **确定因素（Factors）**  
   → 找出会影响测试结果的所有独立变量。  
   *例：操作系统、浏览器、分辨率*

2. **确定水平（Levels）**  
   → 每个因素取几个值。  
   *例：操作系统（Win/Mac），浏览器（Chrome/Safari/Edge），分辨率（1920×1080/1366×768）*  
   → 此处：因素数=3，水平数分别为2、3、2

3. **选择正交表**  
   → 根据“因素数≥实际因素数，水平数≥最大实际水平数”的原则查表。  
   *例：用 L9(3⁴) 表（最多4个因素，每个因素3个水平）*

4. **映射替换**  
   → 把实际因素和水平填到正交表的列和值中，多余的列直接忽略。

5. **设计测试用例**  
   → 正交表的每一行对应一条测试用例。

6. **补充遗漏**  
   → 正交表覆盖的主要是两两组合，需额外补充你认为高风险或业务强相关的组合。

> **记忆口诀**：定因素→定水平→查表→填表→生成用例→补遗漏

### 第2题：is 和 == 有什么区别？

这是Python面试高频题，核心区别在**比较对象不同**：

| 比较符 | 比较内容 | 核心理解 |
|--------|----------|----------|
| `==` | 比较**值（内容）是否相等** | 值相等即为True |
| `is` | 比较**内存地址（id）是否相等** | 必须是同一个对象才为True |

**举例说明：**

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)   # True  → 内容相同
print(a is b)   # False → 两个不同列表对象，内存地址不同
print(a is c)   # True  → c指向同一个对象，id相同
```

**特殊情况（需注意）：**

- 小整数（-5 ~ 256）和短字符串，Python会做**缓存驻留（intern）**，此时 `is` 也可能为True，但这属于实现细节，**不要依赖**。
- `None` 比较时，**永远用 `is None` 或 `is not None`**，不用 `==`，因为None是单例。

> **面试标准回答**：`==` 比较的是值，`is` 比较的是身份（内存地址）。值相等不一定身份相同，但身份相同值一定相等。

### 第3题：流程分析法的使用流程？

流程分析法（也叫**场景法/业务流程图法**）是站在用户角度，覆盖**完整业务流程路径**的用例设计方法，特别适合有状态流转的系统（如订单、审批）。

**标准使用流程（5步）：**

1. **绘制业务流程图**  
   → 画出从起点到终点的所有路径，标注每个节点的判断条件。  
   *例：登录→浏览商品→加入购物车→下单→支付→发货→签收*

2. **确定基本流（Happy Path）**  
   → 最核心、最正常的顺利路径，无任何异常和分支。  
   *例：余额充足、地址正确、一次性支付成功直到签收*

3. **确定备选流（Alternative Flows）**  
   → 正常流程中的分支选择，每条分支走不同的业务方向。  
   *例：选择货到付款 vs 在线支付；选择普通快递 vs 加急*

4. **确定异常流（Exception Flows）**  
   → 每个节点可能触发的错误/中断处理路径。  
   *例：余额不足、库存不足、支付超时、地址解析失败、中途取消订单*

5. **按路径设计测试用例**  
   → 基本流至少1条用例；每条备选流和异常流各设计用例，确保覆盖图中所有箭头方向至少一次。

> **关键原则**：基本流只测1条最顺利的，**所有异常和分支必须单独设计用例**，不能混在一起测。

### 第4题：函数参数以 `*` 和 `**` 打头分别是什么参数、含义、用法及同时使用的要求？

这道题考的是Python变长参数，需要说清楚两个东西。

---

**`*args` —— 可变位置参数**

- **含义**：接收任意多个**按位置传入**的参数
- **类型**：在函数内部，`args` 是一个**元组（tuple）**
- **使用场景**：不确定调用时会传多少个位置参数

```python
def sum_all(*args):
    return sum(args)

sum_all(1, 2, 3, 4)   # 输出10
```

---

**`**kwargs` —— 可变关键字参数**

- **含义**：接收任意多个**按关键字（键值对）传入**的参数
- **类型**：在函数内部，`kwargs` 是一个**字典（dict）**
- **使用场景**：不确定调用时会传多少个命名参数

```python
def print_info(**kwargs):
    for key, value in kwargs.items():
        print(f"{key}: {value}")

print_info(name="张三", age=25, city="上海")
```

---

**`*` 和 `**` 同时使用的要求：**

1. **顺序必须固定**：`def func(a, b, *args, **kwargs):`  
   → 普通参数 → `*args` → `**kwargs`，**顺序不可颠倒**

2. **`*args` 必须在前，`**kwargs` 必须在后**，否则报语法错误

3. **命名可以自定义**（约定俗成用 `args` 和 `kwargs`，但也可改名）

4. **可以只用一个**，不一定非同时出现

---

**补充加分点**（如果问到）：

- `*` 还可用于**解包**：`func(*list)` 把列表拆成位置参数传入
- `**` 用于**解包字典**：`func(**dict)` 把字典拆成关键字参数传入
- Python3.8+ 还支持 **`/`（位置-only参数）** 和 **`*`（关键字-only参数）** 语法，是进阶区分点，可说可不说不扣分。

## 8.8 周六

1. **如何抓取 HTTPS 的包？**

常用工具：Fiddler、Charles、mitmproxy。

基本步骤：

1. 电脑和手机连接同一个局域网。
2. 电脑启动抓包工具，查看代理 IP 和端口。
3. 手机设置 Wi-Fi 手动代理，填写电脑 IP 和端口。
4. 手机安装抓包工具生成的 CA 证书，并设为信任。
5. 重新访问 App，即可抓取 HTTPS 请求并解密查看。

如果 App 使用了 **SSL Pinning（证书绑定）**，仅安装证书仍无法解密，需要使用测试包关闭证书绑定，或通过专业调试方式绕过。

1. **为什么要使用 Cookie 和 Session？**

HTTP 是**无状态协议**，服务器不会自动记住前一次请求的用户信息。

例如，用户第一次登录成功后：

- 服务器创建 Session，保存用户登录状态；
- 服务器把 Session ID 返回给客户端；
- 客户端把 Session ID 保存到 Cookie；
- 后续请求自动携带 Cookie；
- 服务器根据 Session ID 找到对应用户，从而保持登录状态。

Cookie 保存在客户端，容量较小；Session 保存在服务器，安全性相对更高，但会占用服务器资源。现在很多 App 也使用 Token 来保持登录状态。

1. **ADB 的作用是什么？**

ADB 全称是 **Android Debug Bridge，Android 调试桥**，用于电脑与 Android 设备之间的通信和调试。

主要用途：

- 安装、卸载 App；
- 查看连接设备：`adb devices`；
- 查看日志：`adb logcat`；
- 查看 CPU、内存、电量等资源；
- 上传、下载文件；
- 模拟点击、滑动、输入；
- 截图和录屏；
- 执行 Monkey 稳定性测试；
- 启动 Activity、获取包名和进程信息。

1. **App 性能测试的内容和测试方法**

主要关注：

- 启动时间：冷启动、热启动；
- 页面加载和响应时间；
- CPU 使用率；
- 内存占用及内存泄漏；
- FPS、卡顿和掉帧；
- 流量消耗；
- 电量消耗；
- 长时间运行稳定性；
- Crash、ANR 和异常退出。

测试方法：

- 使用真实设备，准备典型业务场景；
- 重复执行相同操作并记录数据；
- 使用 Android Studio Profiler、Perfetto、SoloPi 或 ADB 监控；
- 测量启动时间：

```javascript
adb shell am start -S -W 包名/Activity
```

- 查看内存：

```javascript
adb shell dumpsys meminfo 包名
```

- 查看 CPU 和进程：

```javascript
adb shell top
```

- 查看 FPS 和掉帧：

```javascript
adb shell dumpsys gfxinfo 包名
```

- 使用 Monkey 长时间运行，观察是否出现 Crash、ANR；
- 对比测试前后数据，判断是否存在资源持续增长、响应变慢或流量异常。
